# Localisation — how every string in Fault Lines is translated

Fault Lines ships **seven complete interface languages**: English, French,
Spanish, German, Portuguese, Yorùbá and Arabic (right-to-left). This document is
the whole system: where copy lives, how it reaches the screen, and how to add or
change a language without shipping a half-English page.

## The rule

> Every user-visible statement is translated. Only proper nouns stay as they are.

That means interface copy, navigation, buttons, empty states, error messages,
form hints, screen-reader labels, `title`/`alt` attributes, exported plans,
announcements and toasts all come from a dictionary.

What deliberately stays in English (or its original form):

| Stays untranslated | Why |
|---|---|
| Fault Lines, Strata Drop, GitHub, Next.js, TypeScript, Tailwind, Markdown, CSV, JSON, MIT, OpenAI, SECURITY.md | brand, product and file names |
| The localised product name in descriptive copy — *Lignes de Faille*, *Líneas de Falla*, *Bruchlinien*, *Linhas de Falha*, *Àwọn Ìlà Àṣìṣe*, *خطوط الصدع* | the product name still carries meaning, so the translated form is used inside sentences |
| Student answers, quotes and teacher-typed questions | the teacher's own data — never rewritten |
| Example-classroom answers and cached analyses in `data/` | sample class data, not UI copy; a teacher's own class replaces it |
| `app/opengraph-image.tsx`, `<head>` metadata, `manifest.json`, CSV column names | machine-readable / social-share artefacts, not pages a reader browses in their language |

## Where the copy lives

```
lib/i18n/
  en.ts   ← source of truth (also exports the `I18nKey` union and `Dict` type)
  fr.ts  es.ts  de.ts  pt.ts  yo.ts  ar.ts
lib/i18n.ts        loader: locales, detection, interpolation, Intl formatters
lib/use-i18n.ts    client hooks: useT() / useLocale()
components/T.tsx   translation island for server components
```

Each locale file is a **complete dictionary** — `const fr: Dict = { … }`, typed
against English. There is no `{ ...en }` spread anywhere: that pattern was the
original bug, because a key you forgot to translate silently rendered English in
the middle of a French page. With `Dict`, a missing key is a TypeScript error.

## Getting a string onto the screen

**Client components** use the hook:

```tsx
const t = useT();
<p>{t("riskMix")}</p>
<span>{t("reportAnswers", { n: total })}</span>
<span>{t.sharedNote}</span>       // same object also carries num/date/dateTime
```

`useT()` is hydration-safe: the first client render matches the server (English),
then a mount effect switches to the stored or detected locale and re-renders.
It also returns `num()`, `date()` and `dateTime()` formatters that use `Intl`, so
digits and dates follow the locale.

**Server components** (`app/page.tsx`, `app/privacy/page.tsx`, `app/play/page.tsx`,
the status pages, `SiteFooter`, `StrataLoader`) cannot read `localStorage`, so
they render the English string on the server and use the `T` island:

```tsx
<T k="gapTitle1" />
<T k="receiptChip" vars={{ n: 1 }} />
<T k="footerCopyright" vars={{ year: new Date().getFullYear() }} />
```

`vars` accepts any node, so translations can keep their emphasis:

```tsx
<T k="keyboardHint" vars={{ j: <kbd>j</kbd>, k: <kbd>k</kbd> }} />
```

## Interpolation

Placeholders use `{name}` and are filled by `t(key, { name })`:

```ts
footerCopyright: "© {year} Fault Lines · Every class has fault lines."
expSummary:      "{a} answers · {b} beliefs"
```

Missing values are left visible (`{year}`) rather than blanked, so a typo shows up
in review instead of production. `tests/i18n-coverage.test.ts` enforces that the
placeholder set of every key is identical in all seven locales.

## Changing language

```ts
import { setLocale } from "@/lib/i18n";
setLocale("ar");   // writes localStorage, sets <html lang/dir>, broadcasts
```

- Storage key: `faultlines-locale`
- Event: `faultlines:locale` (every mounted `useT()`/`T` re-renders — no reload)
- `<html lang>` and `<html dir>` update with it; Arabic is the only RTL locale
- The boot script in `app/layout.tsx` applies the stored locale before first paint,
  whitelisted to the seven supported codes (an unsupported browser language falls
  back to English rather than setting `lang="ja"` on an English page)
- Pickers: a compact `<select>` in the header (`components/LanguageSwitcher.tsx`)
  and the full described list in Settings

## Adding a language

1. Copy `lib/i18n/en.ts` to `lib/i18n/xx.ts` and translate every value.
2. Keep every `{placeholder}` byte-identical.
3. Register it in `lib/i18n.ts`: import, add to `locales`, `LOCALE_NAMES`,
   `LOCALE_SHORT`, and to `RTL` if it is right-to-left.
4. Add the code to the whitelist in the boot script (`app/layout.tsx`).
5. Run `npm test` — parity, placeholder and "no English left" checks tell you
   exactly which keys are missing or still English.

## The guard rails

`tests/i18n-coverage.test.ts` fails the build if:

- any locale has a different key set from English;
- a value is empty or still contains `TODO`;
- a `{placeholder}` was dropped or renamed in translation;
- a value is byte-identical to English and is not on the documented allowlist
  of shared spellings (`stat3v: "7"`, French `gamePause: "Pause"`, …);
- fewer than 85 % of short labels differ from English in a locale;
- a non-Arabic locale claims to be RTL.

## Layout notes for RTL

`app/globals.css` drops letter-spacing on Arabic headings and eyebrows, mirrors
the rust rule on blockquotes, and keeps numerals, `code` and `kbd` left-to-right
inside RTL text. Form fields, cards and navigation use logical properties
(`ps-*`/`pe-*`) where direction matters.
